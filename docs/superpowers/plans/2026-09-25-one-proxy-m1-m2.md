### Task 2: protocol/anthropic — canonical 类型（block 级未知字段保留 + header bag）

**Files:**
- Create: `internal/protocol/anthropic/types.go`, `types_test.go`

核心类型（保真要点）：
- `Request`：`Model string / Messages []Message / System json.RawMessage / Stream bool / Extra map[string]json.RawMessage` + `Header http.Header`（beta/version 白名单头随请求走）
- `Message`：`Role string / Content json.RawMessage / Extra` — content 保持 RawMessage，**不深度解析**（这是 block 级保真的实现方式：请求方向我们只改 model 字段，content 原样传输）
- `Response`：`ID/Model/Role/StopReason/Stream / ContentBlocks []ContentBlock / Usage Usage / Extra`
- `ContentBlock`：`ID/Type/Input json.RawMessage / Text string / Extra map[string]json.RawMessage` — 序列化时按 Type 分支重建；未识别 Type 整块原样输出
- `Usage`：`InputTokens/OutputTokens/CacheCreationInputTokens/CacheReadInputTokens`
- `Event`（SSE canonical 事件）：`Type string / Raw json.RawMessage`（message_start/content_block_start/content_block_delta/content_block_stop/message_delta/message_stop/ping/error 之外的类型原样透传）
- 序列化器 `WriteRequest(w, req)` / `WriteResponse(w, resp)`：Extra 字段合并输出
- 事件解码 `ParseRequestStream / ParseResponseStream` 按需（M2 chat SSE 转换用）

测试要点：未知顶层字段（`top_k`）、未知 block 类型（`server_tool_use`）、`thinking`/`tool_use`/`cache_control` 的往返保真（marshal→unmarshal→marshal 字节等价）。

### Task 4: provider — Adapter 接口与渠道状态

**Files:**
- Create: `internal/provider/adapter.go`, `status.go`, `adapter_test.go`

```go
type ErrorKind int
const (
    ErrKindNone ErrorKind = iota
    ErrKindQuota        // 429 配额/限速 → 冷却+切换
    ErrKindAuth         // 401/403 → auth-failed+切换
    ErrKindUpstream     // 5xx/网络 → 切换不改状态
    ErrKindBadRequest   // 400 → 默认不切；body 含 model/max_tokens 允许切一次
)

type UpstreamError struct {
    Kind ErrorKind
    StatusCode int
    Body string
}

type Adapter interface {
    Invoke(ctx context.Context, req *anthropic.Request) (*anthropic.Response, error)
    Stream(ctx context.Context, retryReader func() (io.Reader, error)) (events <-chan anthropic.Event, err error)
    Models(ctx context.Context) ([]ModelInfo, error)
    NormalizeError(err error) ErrorKind
}
.Stream 的 retryReader 参数：router M3 做故障切换重试时需要重新读原始 body（channel 不可读两次）。M1/M2 单渠道单次调用，传 `func() (io.Reader, error) { return bytes.NewReader(savedBody), nil }` 即可。
```

`status.go`：`ChannelStatus`（OK/Cooling/AuthFailed + CoolingUntil time.Time + FailReason string），`Registry`（内存 map[channelID]Adapter 实例 + statuses，读写锁）。Registry 提供 `Get(id)`、`SetStatus`、`SnapshotStatuses`。

测试：状态流转（cooling 过期自动回 OK 判定）、Registry 并发读写。

### Task 6: proxy 入口（/v1/messages + /v1/models + 鉴权）

**Files:**
- Create: `internal/proxy/server.go`, `handlers_anthropic.go`, `models.go`, `auth.go`, `server_test.go`

- `Server` 持有 `Registry`、`config.Store`
- 鉴权：`Authorization: Bearer <key>` 或 `x-api-key: <key>`，匹配 config.LocalKey；失败 401（Anthropic 风格 error body）
- `/v1/models`：聚合启用渠道 Models 去重 → OpenAI 格式 `{object:"list", data:[{id, object:"model", ...}]}`
- `/v1/messages`：
  1. 读 body（io.LimitReader 32MB，图片 base64 上限）
  2. 解析出 model 名（浅解析 struct{Model string}）
  3. M1：选第一条声明该模型的启用渠道（M3 换成 router 完整实现）
  4. 反序列化 canonical Request（注入 Header bag）
  4'. **直连语法检查**：`ch-xxx/yyy` → 直连渠道 xxx 用模型 yyy（M1 实现在 handler，M3 移入 router）
  5. ModelMapping 重写 model（映射存在于则替换）
  6. stream 字段决定 Invoke/Stream；SSE 写回（event: 类型\n + data: JSON\n\n）
  7. M1 usage 先内存计数（M4 换 SQLite）
  8. 失败：按 ErrorKind 返回入口协议错误格式
- SSE 写回规范：每个 canonical Event `w.Write([]byte("event: "+e.Type+"\n"))` + `data: ` + e.Raw + `\n\n`；flush 每 event
- 测试：鉴权 401、models 聚合、非流式/流式端到端（httptest 假上游 + 真 Server）

## M3–M6 后续计划（概要，开工时细化）

- **M3 router**：候选集（Models∧Enabled∧状态可用）→ Priority 降序取最高 → Invoke/Stream 失败按 ErrorKind 决定冷却/切换/400 细分（body 含 model/max_tokens 允许切一次）→ 全不可用聚合人话错误。ch- 直连从 handler 移入 router。冷却内存态。
